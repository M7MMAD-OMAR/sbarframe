# Skill selection

Find current installed paths instead of assuming every optional skill exists. Read the selected SKILL.md before using it. Keep selection in the project's SKILLS.md or DESIGN.md with purpose and verification limits. Do not copy machine-specific paths into buyer instructions.

| Scope | Capability to select | Purpose |
|---|---|---|
| Every Framer build, repair or audit | sbarframe | Scope, quality and evidence coordination |
| Connected editor or API work | Official Framer execution skill and supported CLI | Current APIs, identity checks, edits and readback |
| Custom code | Framer code-component guidance | Controls, sizing and server/static rendering safety |
| Design | UI composition and design-system guidance | Typography, hierarchy, shared tokens and reusable sections |
| Accessibility | Accessibility review | Keyboard, focus, labels, semantics and contrast |
| Motion | Animation performance review | Property ownership, lifecycle and reduced motion |
| SEO | Metadata and crawlability review | Initial HTML, routes and social previews |
| Performance | Browser profiling and image-delivery analysis | Repeatable measurements of the real artifact |
| Media | Asset research or original image creation | Fit, provenance and permitted use |
| Debugging and review | Reproduction, source analysis and visual QA | Fix causes and retest affected consumers |

These are capabilities, not required third-party skill names. Use equivalent available tools; do not install unrelated dependencies. Only Bun is required for the optional bundled helper. Record any missing capability and its verification limit.

Use Framer native effects and project skill examples before reaching for unrelated animation frameworks. HyperFrames is for an actual requested video, not ordinary site motion. React/Next previews, shadcn, Supabase, Figma and hosting skills are conditional on real scope. Do not load them because a reference site uses one.

For substantial work, use independent reviewers if authorized by the owner or applicable instructions. Give each reviewer scope, sanitized current evidence and applicable project identity/recovery rules. Assign distinct component ownership to connected workers. Read-only review is usually sufficient. Reviewers need not mutate a canvas. Record who ran and what was reviewed; a model name must be observed, never guessed.
