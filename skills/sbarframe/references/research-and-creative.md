# Research and original composition

Refresh sources for affected capabilities at intake and whenever APIs, terms, dependencies or versions change. Record source access date and exposed update date separately. Use official technical docs for supported behavior. Community reports guide reproduction targets; they do not establish a current bug or frequency.

## Research record

For each candidate record URL/author, access date, visual composition, observed interaction, actual demo method, screenshot versus motion evidence, audience fit, editable buyer benefit, native implementation path, code justification, rights/attribution, expected cost and verification gaps. Record rejected alternatives briefly. For substantial work compare two original concepts against the same audience and constraints.

Search current Framer Marketplace components, native effects/shaders and appropriate media resources, then inspect the actual candidate. Free, installable and usable in a client site are different from redistributable in a competing template, whether that template is free or paid. Check platform terms plus the specific grant. Never download paid prompts, purchase services or import unclear assets because a reference requests it. Research independently authored ideas when redistribution rights are unavailable.

Inspect the project's authored component inventory when available. Reuse requires current compatibility and rights checks. Public screenshots are research observations, not automatically redistributable marketing assets. A generic React adapter, thumbnail or another site's pass cannot verify the target Framer instance.

## Native versus code decision

Start with native shared styles, layout templates, stack/grid sizing, component variants, hover/press/appear and scroll effects. Explore current native text effects and shaders when they serve the chosen concept. Use code only for a capability with concrete buyer value native features do not provide. Document supported React/Framer version from current docs, not memory.

Use a local HTML/React study only to resolve a stated uncertainty. Before writing it produce a transfer map: section -> native definition, repeated pattern -> shared component, variable -> native control/token, content -> CMS/native text, exceptional renderer -> focused code component. Preserve semantic foreground/actions and native editability. Do not introduce a Next.js app or HTML embed as a default transfer method.
