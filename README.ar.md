# sbarframe

**مهارة لوكلاء الذكاء الاصطناعي لبناء مشاريع Framer قابلة للتعديل، مع بحث وتصميم مشترك وتحقق قبل التسليم.**

[English](README.md) · [دليل الاستخدام الكامل](docs/usage.md) · [مرجع فحص الأدلة](skills/sbarframe/references/gate.md)

![سير العمل من البحث والتصميم إلى البناء والتحقق والإصلاح والتسليم](docs/diagrams/workflow.svg)

تساعد المهارة على معالجة المشاكل التي قد لا تظهر في صورة التصميم: التجاوب،
التحقق من الحقول، تكرار العناصر دون مكونات مشتركة، الحركات المرهقة، الصور
الثقيلة، نقص SEO، وغياب توثيق التعديل. تشمل تعليمات التنفيذ، عقود المكونات،
قوالب توثيق المشروع وأداة لفحص سلامة سجل الأدلة.

## التثبيت

```bash
npx skills add M7MMAD-OMAR/sbarframe --skill sbarframe
```

اختر الوكيل ونطاق التثبيت من واجهة المثبّت. يمكن استخدام `bunx` بدلاً من
`npx`. يدعم دليل الاستخدام التثبيت اليدوي والتحديث وCodex وClaude Code.

اطلب من الوكيل مثلاً:

```text
استخدم sbarframe لإنشاء موقع Framer قابل للتعديل.
ابحث عن اتجاهين إبداعيين، وحدد نظام التصميم والمكونات والحركة.
تحقق من التجاوب والحقول والوصول وSEO والصور والأداء.
وثق ما اختبرته فعلياً وأصلح المشاكل المعروفة قبل قبول التسليم.
```

للتعديل داخل Framer، اتبع أولاً [إعداد الوكلاء الرسمي](https://www.framer.com/agents/external/)
واستخدم مهارة التنفيذ الرسمية. sbarframe تنسّق الجودة ولا توفر اتصالاً أو بيانات دخول.

## طريقة العمل

1. تحديد النطاق والمشروع الصحيح والصلاحيات الموجودة.
2. بحث المراجع والمكونات والحقوق ومقارنة أفكار أصلية.
3. توثيق الأنماط المشتركة وبناء مكونات بخصائص تعديل واضحة.
4. تنفيذ التجاوب والحقول والمحتوى والحركة وSEO وكفاءة الصور.
5. اختبار المحرر وPreview والنشر المصرح به بشكل منفصل.
6. إصلاح العيوب وإعادة الاختبار وتحديث دليل التعديل والتسليم.

النموذج المحلي بـHTML أو React اختياري لحل نقطة غير واضحة. لا يثبت وحده
التوافق مع Framer. لكل عنصر أو مجموعة قرار حركة مقصود أو ثبات مقصود، مع
مراعاة تقليل الحركة واللمس ولوحة المفاتيح.

## أداة المشروع الاختيارية

تحتاج Bun، وتعمل محلياً دون اتصال بالشبكة:

```bash
git clone https://github.com/M7MMAD-OMAR/sbarframe.git
cd sbarframe
bun skills/sbarframe/scripts/project-kit.ts init ../my-framer-site
```

تنشئ المستندات الناقصة وسجل تحقق يبدأ بحالة غير مقبولة. تحفظ الملفات الموجودة.
بعد جمع الأدلة الحقيقية وتعبئة السجل:

```bash
bun skills/sbarframe/scripts/project-kit.ts gate ../my-framer-site VERIFIED_PROJECT_ID EXACT_TESTED_REVISION
```

![مسار الأدلة من الملاحظات الحقيقية إلى التقارير والفحص والمراجعة](docs/diagrams/evidence.svg)

نتيجة `evidenceIntegrityOk: true` تعني أن السجل المقدم اجتاز فحوص السلامة.
الأداة لا تنفذ اختبارات الموقع ولا تثبت صدق التقرير أو خلو الموقع من كل عيب.
لا يجوز نسخ أدلة موقع آخر أو تعبئة حالات نجاح من بيانات الاختبارات البرمجية.
الإصلاح المحدود يمكن أن ينتهي مع بقاء قبول إطلاق الموقع الكامل محجوباً.

## المراجع والتطوير

يوضح [دليل الاستخدام](docs/usage.md) الملفات الناتجة، صيغة الأدلة، سيناريوهات
البناء والإصلاح والتدقيق، وإعداد تعليمات المهارات الأصلية داخل Framer. يوضح
[مرجع اختيار القدرات](skills/sbarframe/references/skill-routing.md) متى تحتاج
إرشادات إضافية للتصميم والمكونات والوصول والصور والأداء.

```bash
bun test
bun run check
```

الاختبارات تستخدم مشاريع اصطناعية مؤقتة وتختبر الأداة. لا تمثل قبول موقع فعلي.
للمساهمة أرسل مثالاً مصغراً خالياً من الأسرار والبيانات الخاصة.
